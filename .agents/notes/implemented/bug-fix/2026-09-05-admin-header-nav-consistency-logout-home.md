# Agent Note: admin-header-nav-consistency-logout-home

Status: implemented

## Problem

Four user-reported UI defects after the Phase-3 unification: (1) every admin subpage carried its own copy-pasted nav that had drifted — /admin/ showed Dashboard/PDF Templates/Rounding Rules/Users/API Keys/Rent Šabloni while /admin/pdf_templates, /admin/users etc. showed older subsets missing Users/API Keys/Rent Šabloni; (2) /admin/rent/templates (and the admin backup downloads) bounced even a logged-in admin into an endless /login?next=/admin/ loop; (3) a red Logout button sat in every app header; (4) the app-menu link was labeled "Landing Page".

## Decision

The admin header is now ONE template, qp_crm/admin/templates/admin/_nav.html: every admin template sets `{% set active = '<name>' %}{% include 'admin/_nav.html' %}` (active ∈ dashboard|pdf_templates|rounding_rules|users|api_keys|rent_templates, optional nav_extra for the editor breadcrumb) and renders all six links plus the Home link on every admin page. The redirect loop's root cause was stale per-route `session['admin_authenticated']` checks (a pre-Phase-3 flag unified login never sets) in admin/routes/rent_templates.py and admin/routes/backup.py — removed; bp.before_request(require_role("admin")) in admin/app.py is the only gate, so an anonymous visitor gets the unified login with ?next=<the requested page> and a logged-in admin gets a 200. Logout buttons are gone from every header (admin nav, pricing/offer base, rent "Odjava"); /settings now hosts one Logout card routing through the unified /logout (auth.logout), matching the logout cards already on the pricing/offer in-app settings pages. Headers label the app-menu link Home (`_('Home')`, sr translation 'Početna strana' added in shared/utils.py; the old 'Landing Page' key was dropped from the sr dict since nothing renders it). Rent keeps its Serbian 'Početna' — same label, same link. Regression coverage lives in tests/smoke/test_smoke_modules.py: gated-route reachability for /admin/rent/templates + /admin/backup_db + /admin/backup_full, one-full-header assertion across all six admin subpages, editor-header assertion for /admin/edit_pdf_template/<id>, settings-app logout/Home assertion, and a no-logout/no-'Landing Page' header assertion across pricing/offer/rent/sale. NOT done: the header still shows for admins only what the admin app is (no cross-app links added); /settings remains public, so its Logout renders for anonymous visitors too (harmless: it just redirects to /login).
## Alternatives considered

**Keep per-template navs and just patch the missing links into each copy** — lost because that is exactly the drift that produced this bug; the next admin page would reintroduce it. **A Jinja macro with arguments instead of an include with `{% set %}` variables** — equivalent power but a different idiom than the codebase uses anywhere else (no macros today); the include+set form keeps template diffs one-line. **Fix the loop by making the routes set admin_authenticated instead of removing the checks** — lost because it would resurrect a dead per-module flag alongside require_role and leave two gates to keep in sync. **Hide the settings-app logout for anonymous users** — rejected as pointless state-dependent styling for a link that is harmless when logged out.
## Consequences

Cost: admin header changes now live in one file (an include), so a template rendered standalone (without the include variable set) would crash with an undefined-variable error — every admin template must keep its `{% set active %}` line; smoke tests pin this for all six pages plus the editor. The stale-flag removal widened /admin/backup_db and /admin/backup_full from "flag AND role" to "role only" — strictly a bug fix since the flag could never be true post-Phase-3, but it means those downloads now depend entirely on require_role freshness. Golden-PDF tests stay red on the host (fonts) — unrelated to this change but discovered while verifying: baselines are pinned to the docker image's fonts-dejavu-core, so host runs must not re-baseline.
