# Agent Note: qp-crm-package-move

Status: implemented

## Problem

QP-CRM's application code sat as eight top-level modules/packages (main.py, wsgi.py, shared/, services/, pricing/, offer/, rent/, admin/, sale/, settings/) importable only because every entrypoint appended the repo root to sys.path. That is fragile (import success depends on CWD/entrypoint), ambiguous at top level (generic names like shared, services, settings), and blocks any packaging or tooling that expects a real package tree — without changing a single URL or runtime path, since Docker bind mounts and config-derived paths anchor at the repo root.

## Decision

All application code lives in qp_crm/ (qp_crm/main.py, qp_crm/wsgi.py, qp_crm/{shared,services,pricing,offer,rent,admin,sale,settings}/), moved with git mv so history survives: 93 renamed paths, 69 byte-identical and 24 carrying import edits. Every app-package import is now package-absolute (`from qp_crm.shared.config import ...`, including lazy function-level imports like offer/routes/pdf.py's pdf_service and the bare `from qp_crm.services import ...` aggregator in services/__init__.py); relative imports (`from ..app import ...`, `from . import routes`, shared/db.py's `from .config import DATABASE`) are untouched and unchanged in meaning. All eight sys.path bootstrap blocks are deleted (pricing/app.py, pricing/api_v1.py, offer/app.py, rent/app.py, admin/app.py, sale/app.py, settings/app.py, wsgi.py) along with their now-unused `import sys` lines; a repo-wide grep confirms zero `sys.path` and zero old-form imports under qp_crm/ and tests/. Path anchoring: qp_crm/shared/config.py computes BASE_DIR with three dirnames (file -> shared/ -> qp_crm/ -> repo root) and every other constant still derives from it — BASE_DIR, STATIC_DIR, APP_DATA_DIR, DATABASE, IMAGE_DIR, APP_ASSETS_DIR print values byte-identical to pre-move. qp_crm/main.py passes template_folder=os.path.join(BASE_DIR, 'templates') so the landing templates stay at <root>/templates/; qp_crm/admin/app.py derives PACKAGE_DIR from its own __file__ for the offer filesystem-template seeding and takes pdf.css from STATIC_DIR; qp_crm/rent/import_templates.py anchors the legacy "excell Rent calc" DOCX_DIR at BASE_DIR (its old dirname(HERE) anchor silently became qp_crm/ after the move — fixed). Blueprint template_folder="templates" needs no change because blueprints resolve against their module's root_path and the templates moved with the code. Entry points: Dockerfile CMD is qp_crm.wsgi:application; run_apps.sh and restart_app.sh run `python -m qp_crm.main` (pkill/pgrep patterns updated to match); deploy.sh and docker-compose.yml needed no functional change. Tests import qp_crm.* with conftest.py's PROJECT_ROOT sys.path insert kept as the one remaining (test-side) bootstrap. NOT done: no compat shims, no old-name aliases, no __init__.py added to the four namespace module dirs, no .gitignore/doc-comment cleanups beyond files the move made misleading, nothing committed (all changes left uncommitted in the working tree for the delegating agent).
## Alternatives considered

**Keep flat layout + sys.path hacks, only clean them up.** Lost: hacks are per-entrypoint boilerplate that every new module would copy, and `import shared` at top level collides with the generic name on sys.path; the package form makes the app importable from any CWD with zero path manipulation.

**Backward-compat aliases (sys.modules['shared'] = qp_crm.shared etc.) so old imports keep working during a transition.** Lost: the repo has exactly one consumer set (itself + tests), all rewritten in the same commit-equivalent change; aliases would preserve two true names for every module and defeat the point of the move.

**Move templates/, static/, app_data/ into qp_crm/ too.** Lost: docker-compose bind-mounts ./app_data, ./app_assets and ./static/img into the container at those literal paths, and shared/config.py must keep producing those exact absolute values; relocating them would require compose + config + deploy changes for zero behavioral gain.

**Add __init__.py to pricing/offer/admin/settings while moving.** Lost: those four were importable namespace directories before the move (no __init__.py), and PEP 420 namespace subpackages inside a regular package resolve fine on Python 3.12 (verified: import qp_crm.pricing -> _NamespacePath). Adding them would be new files with no behavioral need; can be added later if tooling ever complains.
## Consequences

Bought: no sys.path mutation anywhere in app code (verified by grep), unambiguous qp_crm.* imports, package importable from any CWD, and the pytest isolation contract unchanged (conftest still patches qp_crm.shared.config attributes before any app-module import; test_infra_isolation still proves qp_crm.shared.db binds from that same module object). Cost: every path constant that derived "parent of module dir = repo root" had to be re-audited — four were found and re-anchored (config BASE_DIR, main template_folder, admin PACKAGE_DIR/STATIC_DIR, rent DOCX_DIR); a future module must use qp_crm.shared.config.BASE_DIR, never dirname(dirname(__file__)). Cost: stale references remain intentionally in historical docs (AUDIT_FINDINGS.md, PROGRAM_DOCUMENTATION.md, .gitignore's custom_libs comment) and in wsgi.py's stale line-number citations — cosmetic only. Follow-up: pricing/offer/admin/settings still lack __init__.py (namespace dirs); the vendored custom_libs/markdown is now fully unused by imports and could be deleted in a later stage.
