# Agent Note: qp-crm-phase-2-structural-refactor

Status: implemented

## Problem

QP-CRM ran six separate Flask instances (one per module) with duplicated helpers, two drifting schema-init paths, 1.2–1.8k-line route files, sys.path hacks, a vendored markdown library, and DB-stored PDF templates rendered through the full app Jinja environment (audit C4: SSTI via admin UI). Money logic was untestable without HTTP, and five latent bugs were pinned by characterization tests but unfixed.

## Decision

Branch phase-2-refactor (12 commits, dff048e..9217633) shipped seven structural stages with a zero-behavior-change discipline enforced by byte-identical golden PDFs (/tmp/qp-crm-tests fixed paths, tests/golden/baselines/) and the Docker pytest gate after every step. Shipped reality: ONE Flask app in qp_crm/main.py registers all seven blueprints (prefixes unchanged, per-module auth flags pricing/offer/rent/admin_authenticated, one qp_session cookie + QP_SECRET_KEY; DispatcherMiddleware deleted). All app code lives under the qp_crm/ package: shared/ (web helpers, config with BASE_DIR = three dirnames so deployment paths are IDENTICAL to pre-move, schema.py as the single DDL source with guarded migrations), services/ (pricing/offer/rent/pdf services moved verbatim; pdf_service renders DB templates with jinja2.sandbox.SandboxedEnvironment autoescape=True closing C4; rent documents use literal substitution — no Jinja surface), per-module routes/ packages whose app.py bottoms out with "from . import routes". Dockerfile CMD qp_crm.wsgi:application (self-initializing boot); CI (.github/workflows/ci.yml) runs docker compose build + pytest. After byte-verification, the five BUG cards were fixed one-commit-one-test each in their new homes: rent pmt/calculate_rent total for period_months<=0; generate_schedule raises ValueError -> 400 in schedule PDF routes (also surfaced and fixed a stage-5 defect: rent/routes/__init__.py had omitted pdf.py, killing 3 routes since the split); offer recalc_totals normalizes all four percentage columns to 0.0 (single encoding); pricing apply_rounding NEAREST = Decimal ROUND_HALF_UP (Excel-aligned) and val<=0 sign-preserving, bracket selection deliberately unchanged; sale degrades to empty state/404 on a bare schema. Exit criteria all met; suite 133 passed; image tagged qp-crm:phase2.
## Alternatives considered

**Big-bang rewrite on a modern stack** — rejected per the standing architecture-direction card: the codebase earns its keep and the golden-PDF byte-identity harness only pays off on an evolved codebase. **Fixing the five bugs during the structural stages** — rejected because mixing behavior changes into refactor steps would have invalidated every green suite as a regression gate; bugs were deferred until the structure was byte-verified. **Migrating money math to Decimal end-to-end in stage 4** — rejected as out of scope (audit L11 stays Phase 3); only the NEAREST method went Decimal, verbatim otherwise. **SQL-file schema source** — rejected: python DDL expresses idempotent guarded migrations (add_column_if_missing, COLLATE NOCASE partial unique index, legacy-UNIQUE rebuild) precisely. **Auto-discovery of route modules instead of explicit __init__ imports** — rejected: explicit lists make route registration auditable, but the stage-5 pdf.py omission shows the trade: route counts must be checked when adding modules (now covered by route-level regression tests).
## Consequences

Bought: one session/secret, one schema source, sandboxed PDF-template rendering (C4 closed), money logic unit-testable in isolation, 121→133 tests, CI on GitHub Actions, no vendored libs, clean package layout. Costs and follow-ups: rent/routes/__init__.py-style explicit module lists can silently drop routes if a new module isn't registered (regression tests now guard the known set); characterization pins were deliberately re-baselined in four places with bug-card references — future readers must read those cards before "restoring" old expectations; deferred debt now explicit on the board: H10 bare-numeric input validation, L9 fresh-connection-per-call, L11 float money, bracket-selection semantics product decision, unified auth/CSRF (Phase 3). Manual user testing of qp-crm:phase2 is the next step before Phase 3 starts.
