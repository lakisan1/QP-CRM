# Agent Note: admin-routes-domain-split

Status: implemented

## Problem

admin/app.py had grown to 1296 lines mixing blueprint setup, DDL/init functions, a backup helper and all 29 admin routes. Phase 2 stage 5 requires per-domain route modules so each admin concern (auth/dashboard, settings, presets, PDF templates, backup, rounding rules, rent template editor) is editable and reviewable in isolation — without any behavior change in an already-green codebase.

## Decision

admin/app.py (186 lines) now keeps only: imports (unchanged, some now intentionally unused), the sys.path shim, the Phase-2 header comment, `bp = Blueprint("admin", ...)`, init_presets_table/init_pdf_templates_table/init_rounding_rules_table/init_db, the `bp.before_request(make_auth_hook(...))` hook, and the non-route helper `generate_full_backup_zip()`. Its very last line is `from . import routes  # noqa: E402,F401` (preceded by a two-line stage-5 comment), which imports admin/routes/ — a regular package whose __init__ does `from . import core, settings, presets, pdf_templates, backup, rounding, rent_templates  # noqa: F401`. The 7 domain modules (core 3, settings 7, presets 3, pdf_templates 6, backup 5, rounding 3, rent_templates 2 routes) hold the route functions byte-verbatim. Each module imports flask/stdlib names directly, `shared.config` paths (STATIC_DIR/DATABASE/APP_ASSETS_DIR/IMAGE_DIR) and the `shared.web` constants MANDATORY_FIELD_KEYS/RENT_DEFAULT_KEYS directly from their sources, and gets every admin.app-namespace helper (get_db, check_password, set_password, get_api_key, generate_api_key, revoke_api_key, get_country_list, fetch_mandatory_fields, fetch_rent_defaults, sort_rent_templates, DEFAULT_RENT_EMAIL, generate_full_backup_zip) via `from ..app import`. The two API-key routes (api_key_generate/api_key_revoke) live in settings.py — they are password-gated settings mutations like update_passwords. Negative guarantees: route bodies are byte-identical to the originals (verified by diffing each module's code region against `git show HEAD:admin/app.py` chunks); app.py's imports were NOT pruned; docker/tests were not run (out of scope) — verification was AST-parse, 29-decorator tally, route-multiset diff, name-coverage scan, and an import smoke test registering the blueprint on a throwaway Flask app (29 endpoints, identical URL rules, auth hook present; the venv lacks `markdown`, so that smoke test stubbed it — real runtime verification needs the docker env).
## Alternatives considered

**Move generate_full_backup_zip() into admin/routes/backup.py.** Rejected: the stage-5 plan explicitly keeps non-route helpers in app.py, and main.py/wsgi.py/tests import from admin.app — leaving the helper in place keeps every existing `from admin.app import X` working unchanged. **Import shared.db/shared.auth/shared.countries/shared.web names directly in route modules instead of via `from ..app import`.** Rejected: the task spec names get_db/get_api_key/.../DEFAULT_RENT_EMAIL as `..app` imports; routing them through admin.app keeps one import surface and is byte-equivalent at runtime (same objects). Only the shared.web *constants* (MANDATORY_FIELD_KEYS/RENT_DEFAULT_KEYS) and shared.config paths are imported from their sources, per the spec's "copy the exact import sources" rule. **Keep `import re` mid-file in pdf_templates.py where it sat in app.py.** Rejected: the spec requires each route file to start with docstring + imports only; `re` (used solely by cleanup_images) moved to the module header — same module namespace, zero behavior delta.
## Consequences

Bought: admin domain work is now isolated per file; the pattern (domain module + `from ..app import bp, ...` + bottom `from . import routes`) is the template the remaining stage-5 module splits follow. Cost: route code can only use names defined in admin.app ABOVE the bottom registration import — anything a route needs must be defined or imported there first, or it becomes a new helper in shared/; blueprint registration ORDER differs from the old single-file order (harmless: werkzeug matches by rule specificity and all endpoints/URLs are unchanged, verified against the pre-refactor route multiset). The smoke test's `markdown` stub is throwaway (/tmp) — the venv still lacks the real dependency, so full runtime/pytest verification remains a docker-env task.
