# Agent Note: qp-crm-dockerization

Status: implemented

## Problem

QP-CRM could only run via run_apps.sh (sudo apt + venv + git-pull/pkill/nohup flow — audit M11), and this machine could not boot it at all: module-level WeasyPrint imports in offer/app.py:8 and rent/app.py:10 fail on the missing host libpango. There was no reproducible runtime, no update path that preserved data, and secret keys were baked into source for pricing/offer/rent.

## Decision

QP-CRM ships as one container. Dockerfile: python:3.12-slim + the run_apps.sh PKGS set (libpango-1.0-0, libpangoft2-1.0-0, libharfbuzz-subset0, libgdk-pixbuf-2.0-0, libcairo2, shared-mime-info, fonts-dejavu-core) + tzdata, ENV TZ=Europe/Belgrade, non-root appuser uid/gid 1000, and — critically — RUN chmod -R a+rX /app after COPY, because COPY preserves host file modes and tool-created mode-600 files made non-root gunicorn die with PermissionError on /app/wsgi.py. gunicorn runs --workers 2 --threads 4 --preload --bind 0.0.0.0:5000 wsgi:application with debugger/reloader off (audit C1). wsgi.py makes every WSGI boot self-initializing: it creates APP_DATA_DIR/IMAGE_DIR/APP_ASSETS_DIR via shared.config, then replays main.py's exact init sequence (pricing_init_db → pricing_migrate_schema → offer_init_db → admin_init_db → rent_init_db) with loud failures, before 'from main import application'; a connection audit confirmed no module-level SQLite connections anywhere, so --preload fork is safe and init runs once in the master. docker-compose.yml bind-mounts ./app_data, ./app_assets, ./static/img (logo upload writes static/img; without the mount it is lost on rebuild), injects secrets from required env_file .env (six *_SECRET_KEY vars; .env.example checked in, .env git-ignored and generated with secrets.token_hex), restart unless-stopped, healthcheck = python stdlib urllib against /api/v1/health with 60s start_period (slim image has no curl). deploy.sh replaces the git-pull/pkill update flow: git pull --ff-only (non-fatal warning on failure, SKIP_PULL=1 to skip) → docker compose build → up -d → ~90s docker-inspect health poll with fail-fast on unhealthy and log dump; run_apps.sh stays untouched for bare-metal users. pricing/offer/rent secret keys now read os.environ.get('PRICING|OFFER|RENT_SECRET_KEY', <old literal dev fallback>), matching the existing admin pattern. custom_libs/ (vendored markdown, sys.path-loaded) was removed from .gitignore and committed — a fresh clone + docker build needs it in-repo. Everything committed per step on branch phase-0-docker, tagged phase-0, image qp-crm:phase0 (382MB); automated smoke checklist (health, 4 logins, product+price, offer PDF 386KB, rent PDF 44.5KB, backup SQLite 221KB) is fully green.
## Alternatives considered

**Alpine base** — musl breaks WeasyPrint/pango and glibc wheels; slim+apt is the proven lib set. **Named volumes** — lost: bind mounts reuse the existing host app_data/, keep the WAL DB inspectable/backable, and uid 1000 matches host dsh so permissions just work. **Schema creation at build time** — data must live in volumes and be created at runtime; init-in-wsgi is what makes any WSGI server boot work. **Random token_hex secret fallbacks (settings/app.py style)** — new key per boot invalidates all sessions on restart; the stable old literals are safer as fallbacks while env wins in Docker. **Subagent-authored Dockerfile** — three attempts stalled closing turns before writing the file; the orchestrator wrote it directly (nudge-and-retry protocol worked for multi-step agents but not single-file writers).
## Consequences

Bind mounts couple the container to host uid-1000 ownership — correct here, needs revisiting only on a host with different uid. Pinned requirements.txt must be regenerated deliberately (pip freeze re-pins whatever is installed). Smoke data now lives in app_data/pricing.db (Smoke Test Product + price, offer SMOKE-2026-001, rent client/equipment/contract 010926) — the user should ignore or delete it before real use. Real generated secrets sit in host .env (chmod 600, git-ignored); losing it invalidates sessions but nothing else. Fresh clones now build reproducibly, at the cost of a 660KB vendored lib in git until Phase 2 swaps it for pip Markdown. deploy.sh fails closed if the container never turns healthy — with the old nohup flow a broken boot looked like success.
