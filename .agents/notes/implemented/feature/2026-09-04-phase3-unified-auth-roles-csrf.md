# Agent Note: phase3-unified-auth-roles-csrf

Status: implemented

## Problem

QP-CRM ran four independent per-app plaintext passwords (admin/pricing/offer/rent in global_settings), every POST form was CSRF-0, no roles existed (any module password opened any module's gate), the API had one shared unattributed key, and there was no login audit or brute-force defense. Phase 4 (new modules) was gated on fixing this without breaking the pinned money-math/PDF behavior from Phase 1's test net.

## Decision

Branch phase-3-auth ships a single users table in the one shared schema (10 commits cb3da82..15a568a, image qp-crm:phase3, 218 tests green). Identity: one qp_session cookie for the whole stack; /login + /logout + /change-password live on a top-level auth blueprint, old per-app login URLs redirect. Passwords are werkzeug scrypt hashes only — seeding migrates the four legacy global_settings passwords (legacy value wins over DEFAULT_PASSWORDS) straight to hashes, staff accounts get must_change_password=1 (forced /change-password redirect enforced by require_role re-reading the users row per request), legacy plaintext keys are scrubbed on every boot, and any row restored as plaintext is rehashed transparently at first successful login (check_password + _is_werkzeug_hash, which must accept scrypt's TWO-$ format). Authorization: shared/web.py require_role(*roles) as a before_request hook per blueprint (admin→admin, pricing/offer/rent→staff+admin, sale/settings/api_v1/health public). CSRF: the settings-app token pattern generalized into shared/web.py (csrf_token()/check_csrf(), form field _csrf_token or X-CSRF-Token header, POST/PUT/PATCH/DELETE) hooked app-wide in main.py; all 54 POST forms + AJAX fetches tokenized; api_v1.* exempt (Bearer, not cookies). Users UI at /admin/users (create/deactivate/role/reset, each confirming the acting admin's own password via confirm_current_password; guards: no self-deactivation, no self-role-change, last-active-admin cannot be deactivated/demoted — the last guard is service-level only, unreachable via the UI by construction). Per-user API keys in api_keys (sha256 hash + 12-char prefix, raw shown exactly once), resolve_api_identity prefers user keys then the deprecated-but-valid global key, refused keys (revoked/deactivated holder) resolve to user-denied and are still audited; api_audit logs every authenticated call with username attribution. Login attempts write login_audit (ts, username, ip, success, detail); lockout is an in-process dict keyed (ip, username) under threading.Lock — 5 failures/15min window → 15min lockout, checked BEFORE password verification, cleared on success. Sessions: permanent=True at login + 8h PERMANENT_SESSION_LIFETIME + SESSION_REFRESH_EACH_REQUEST (sliding). Negative guarantees: no plaintext at rest (pinned by test), require_role never trusts the session's role copy, login never enumerates users, auditing never breaks a response (best-effort try/except).
## Alternatives considered

**Flask-Login + Flask-WTF** — rejected: the card forbids new framework deps, and hand-rolled session identity + the existing settings-app token pattern needed zero additions while staying auditable line-by-line. **Redis/memcached rate limiting** — rejected: no new services allowed; a locked dict keyed by (ip, username) with lazy window pruning is sufficient for a single-container LAN app. **Deleting users** — rejected: offers/contracts keep authorship and audit trails; deactivation (is_active=0) blocks login (get_user filters inactive) and kills live sessions on the next request because require_role re-reads the row. **Hard-deleting the legacy global API key** — rejected for now: existing integrations (webshop sync) would break mid-deploy; it stays valid and flagged deprecated in API_INSTRUCTIONS.md and the dashboard card until integrations migrate. **JWT tokens for the API** — rejected: revocation semantics would need extra storage; sha256-hashed random keys with an is_active flag give instant revocation + audit attribution.
## Consequences

Bought: one login/one cookie for six modules, roles enforced per request, every state-changing POST CSRF-protected, per-user API attribution, brute-force slowdown, forced first-login rotation — with 50 new auth tests and zero changes to money-math/PDF code paths (characterization + golden untouched). Cost: tests now share a session-scoped temp DB that PERSISTS across docker pytest invocations, so state-mutating tests must self-heal (reset helper pattern in test_user_management.py); session.clear() at login invalidates the pre-login CSRF token, so tests mint one post-login (real browsers re-mint on the next page render); the lockout dict is per-process — a gunicorn restart clears it (acceptable: counters reset, not a security hole); the transitional dashboard password fields and global API key remain and must be retired in a later phase; live DB gets the users/api_keys/api_audit/login_audit tables on next boot (admin_init_db).
