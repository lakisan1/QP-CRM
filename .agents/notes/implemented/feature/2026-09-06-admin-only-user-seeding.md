# Agent Note: admin-only-user-seeding

Status: implemented

## Problem

After Phase 3, four accounts existed with publicly documented default credentials (Admin1/Price1/Offer1/Rent1) and no forced first-login change, because the change-password self-service was retired mid-phase. The user decided the right posture for a system that will serve ~30 real users is: no default users beyond the admin bootstrap — every staff account is created by the admin in Admin → Users.

## Decision

Shared/auth.py LEGACY_ACCOUNT_SEEDS now contains only ('admin', 'admin'); seed_users_from_legacy (called on every boot in admin.init_db and by factory reset in admin/routes/backup.py) therefore creates exactly one account — the admin bootstrap — from the legacy 'admin_password' global_settings row when present, else DEFAULT_PASSWORDS['admin'], always stored as a werkzeug hash. Staff accounts (pricing/offer/rent) are NEVER auto-created anywhere: fresh volumes, factory resets, and restores of pre-Phase-3 backups all yield an admin-only users table; the admin creates every staff user in Admin → Users. The live app_data/pricing.db had its pricing/offer/rent rows (+ user_modules children, FK order) deleted and was verified over HTTP (staff logins return the login page, admin/Admin1 still logs in). Tests: tests/conftest.py provisions the three staff accounts the auth suite needs via provision_staff_accounts() (same usernames, DEFAULT_PASSWORDS credentials, all module grants, modules_set=CURRENT_MODULE_VERSION), so login/role/module/hash tests are unchanged; tests/auth/test_users_seed.py was rewritten to pin the new contract on in-memory DBs (only admin seeded, staff never auto-created, deleted staff not resurrected by later seed runs, admin legacy password wins, idempotent); the factory-reset and pre-Phase-3-restore tests in tests/auth/test_password_hashing.py assert {'admin'} only and re-provision staff afterward. Suite: 245 passed, 3 skipped (golden PDFs skip outside the pinned image, by design). Docs updated: DOCKER.md and PROGRAM_DOCUMENTATION.md account sections (admin-only, no default staff). Committed as 4f3a2a1 on phase-3-auth. NOT done: rotating the admin account's own seed password (Admin1) — that remains a user action card in Admin → Users; .gitignore does not yet exclude the *.bak backup file.
## Alternatives considered

**Rotating the four seed passwords in the Admin UI** (original grading recommendation) — rejected by the user in favor of deleting the default staff accounts outright ('only admin; I as admin will create all needed users'). **Deleting the live rows without a code change** — rejected after inspection: seed_users_from_legacy re-creates a missing username on the next boot from DEFAULT_PASSWORDS (legacy keys were already scrubbed), so the deletion would not survive a restart. **Empty-users-table-only bootstrap** (seed all four only when the table is empty) — rejected: it would keep default staff accounts on every fresh volume and factory reset, exactly what the user ruled out. **Keeping self-service forced first-login change** — already retired in Phase 3 (admin-managed passwords); not reopened.
## Consequences

Cost: the live DB no longer contains pricing/offer/rent accounts, so any integration or habit that logged in with those credentials breaks (intended). The running container on :5000 still runs the OLD image (built before commit 4f3a2a1): if it restarts before the user redeploys, the old seed logic recreates the three staff accounts from DEFAULT_PASSWORDS fallback — a redeploy (SKIP_PULL=1 ./deploy.sh) makes the admin-only behavior permanent. Backup of the pre-deletion DB: app_data/pricing.db.pre-default-user-removal.20260906-140914.bak (WAL-safe sqlite backup; delete once the new deploy is confirmed). Bought: fresh installs, factory resets, and restored pre-Phase-3 volumes no longer carry default staff accounts; deleted staff rows stay deleted across reboots; DOCKER.md/PROGRAM_DOCUMENTATION.md account docs now match reality. Test-suite note: conftest provisions staff accounts for the auth suite (provision_staff_accounts), so the tests no longer exercise the production seed path for staff — the admin-only seed contract is pinned by tests/auth/test_users_seed.py against in-memory DBs.
